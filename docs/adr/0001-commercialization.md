# ADR 0001. 개인용 면접 앱을 취업 준비생용 서비스로 바꾼다

- 상태: 채택
- 날짜: 2026-11-07
- 기준 코드: 태그 `m0-baseline`(`d1f89c4`)

## 배경

지금 코드는 한 사람이 쓰는 기술 면접 앱이다. 폰이 예약 시간에 알람을 울리고, 받으면 턴제 음성으로 질문과 답을 주고받는다. PC 서버가 답변을 저장한 뒤 Claude로 채점하고 꼬리질문을 정한다. 개인용 계획의 M0~M6을 모두 마쳤다.

상용화 마스터플랜 v1.0(2026-11-03)은 이 앱을 일반 취업 준비생이 자기 자료로 연습하는 AI 면접 코치로 바꾸는 계획이다. 이 문서는 그 계획에서 코드 방향을 정하는 결정과, 지금 코드에서 바꿔야 할 곳을 기록한다.

## 결정

- **대상:** 개발자만이 아니라 일반 취업 준비생 전체다. 초기 검증은 직무 3~5개로 좁힌다.
- **입력:** 처음에는 PDF·DOCX·TXT 자료와 지원 직무·채용공고만 받는다. Notion과 GitHub 연동은 그 다음이다.
- **음성:** 지금의 턴제(음성 인식 → 텍스트 채점 → 음성 합성)를 유지한다. 실시간 끼어들기 음성은 만들지 않는다.
- **서버:** Spring Boot 모놀리스를 유지하고 도메인별로 패키지를 나눈다. 저장소는 PostgreSQL과 파일 저장소를 쓰고, 자료 분석은 비동기 작업으로 한다. Kafka, MSA, 벡터 DB는 처음에 쓰지 않는다.
- **클라이언트:** Android 앱을 유지하고, 자료 업로드와 리포트용 웹 화면을 추가한다. iOS는 이후에 한다.
- **모델:** 채점과 꼬리질문은 Sonnet을 기본으로 한다. 계획서는 자료 추출에 Haiku를 쓰자고 하지만, 개인용 평가에서 Haiku 채점이 기준을 넘지 못했으므로 Haiku를 쓰는 작업마다 평가셋으로 먼저 확인한다.
- **과금:** 무료 체험, 월 구독, 추가 면접 크레딧으로 한다. 가격은 실제 원가를 측정한 뒤 정한다.
- **순서:** 사용자 격리, 자료 기반 면접, 평가 검증, 원가 상한, 결제 순으로 진행한다. 사용자 격리가 끝나기 전에는 다른 사람의 자료를 받지 않는다.

## 그대로 쓰는 것

- 답변을 먼저 저장하고 트랜잭션 밖에서 Claude를 부르는 흐름(`InterviewStore`, `InterviewOrchestrator`, `ClaudeClientAdapter.call`의 트랜잭션 검사)
- 앱이 만든 `clientRequestId`로 재전송을 구분하는 멱등 처리
- 폰의 `AlarmManager` 예약 알람과 턴제 음성 처리
- Flyway 증분 마이그레이션과 Testcontainers 기반 테스트

## 지금 코드에서 바꿔야 하는 곳

코드에서 직접 확인한 내용이다.

1. **인증이 한 사람용이다.** `ApiTokenFilter`는 고정 토큰 하나(`APP_API_TOKEN`)를 비교하고, 맞으면 모두 `owner`로 인증한다. 세션·질문·복습 데이터에 소유자 열이 없다.
2. **전역 유일 제약이 사용자 사이에서 충돌한다.**
   - `review_item.concept_key`의 `uq_review_item_concept_key`(V3)와 `ReviewItemRepository.add`의 `ON CONFLICT (concept_key)`: 다른 사용자의 복습 상태를 덮어쓴다.
   - `question_bank.question_text`의 `uq_question_bank_question_text`(V2): 두 사용자가 같은 질문을 저장할 수 없다.
   - `interview_session.scheduled_date`의 `uq_interview_session_scheduled_date`(V1, 예약 면접만): 같은 날 예약 면접을 한 사람만 시작할 수 있다.
3. **사용량 상한이 서비스 전체 기준이다.** `ApiUsageService.ensureWithinDailyLimit`은 모든 호출의 하루 토큰 합계를 상한과 비교한다.
4. **사용량 로그로는 면접 1회 원가를 다 설명할 수 없다.** `api_usage_log`에는 세션, 모델, 입력·출력 토큰, 추정 비용만 있다. 작업 종류(질문 생성·채점), 성공 여부, 지연 시간, 캐시 토큰이 없다. 사용량은 응답을 받은 뒤에 기록하므로 응답 없이 실패한 호출은 남지 않는다. 세션을 시작할 때 만드는 첫 질문의 생성 호출은 세션이 생기기 전이라 `session_id` 없이 기록된다.
5. **프롬프트와 시드가 기술 면접 전용이다.** `prompts/grading.md`와 `prompts/question-generator.md`는 기술 면접을 전제한다. 시드 질문(`seed/flowticket-questions.json`)은 개인 프로젝트 FlowTicket 문서에서 나왔다.
6. **삭제 범위가 세션뿐이다.** 지금은 세션 삭제(`DELETE /api/v1/sessions/{id}`)만 있다. 계정 삭제와 업로드 자료 삭제는 새로 설계해야 한다.

## 하지 않는 것

계획서의 초기 비목표를 따른다.

- 실제 전화번호로 거는 전화
- 합격 가능성 예측, 인성 진단, 기업 공식 평가 대체
- 실시간 끼어들기 음성
- 다국어 면접, 기업용 평가 플랫폼, MSA·Kafka·EKS 운영
- Notion 페이지나 GitHub 저장소를 제한 없이 자동 수집하는 기능

## 영향

- 개인용 앱과 같은 폰·같은 PC에서 돌 수 있게 앱 ID, 서버 포트, Docker 프로젝트 이름을 분리했다(PR #1).
- 규칙 문서(`docs/rules/`)에 남은 1인 사용 전제는 해당 부분을 바꾸는 단계에서 고친다.
- 지금 API와 스키마는 [docs/baseline](../baseline)에 기록했다. 이후 변경은 이 기준과 비교한다.
