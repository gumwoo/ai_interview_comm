# Git·이슈·PR 규칙

공개 저장소 [gumwoo/ai_interview_comm](https://github.com/gumwoo/ai_interview_comm) 기준이다.

## 이슈

- 구현 단계(M0~M6)마다 이슈를 하나 만들고, 계획서 10.1의 완료 기준을 체크리스트로 넣는다.
- 단계에 포함되지 않은 버그나 할 일을 발견하면 이슈로 남긴다. 해당 단계 안에서 바로 고칠 것은 따로 만들지 않는다.
- 이슈에는 현상과 재현 방법, 또는 할 일과 완료 조건을 적는다.

## 브랜치

- `main`에 직접 푸시하지 않는다. 첫 커밋만 예외로, 저장소 초기 구성을 올릴 때 사용한다.
- 브랜치 이름은 `feat/m0-backend-base`, `fix/duplicate-grading`, `docs/seed-rules`처럼 유형과 내용을 적는다.
- 머지한 브랜치는 삭제한다.

## 커밋

- 메시지는 `유형: 요약` 형식이다. 유형은 `feat`, `fix`, `refactor`, `test`, `docs`, `chore`다.
- 한 커밋에 한 가지 의도만 담는다.
- `Co-Authored-By`로 AI 도구를 공동 작성자에 넣지 않는다.
- 커밋 전에 비밀값과 제외 대상 파일이 들어가지 않았는지 확인한다. 대상은 [CLAUDE.md](../../CLAUDE.md)에 있다.

## PR

- 단계나 기능 단위로 올리고, `Closes #번호`로 이슈와 연결한다. 한 단계가 크면 여러 PR로 나눈다.
- 본문에는 다음을 적는다.
  - 변경 내용과 이유
  - 검증한 것(실행한 테스트와 결과)
  - 검증하지 못한 것(실기기 미확인 등)
- 측정값과 예상값을 구분해 적는다.
- 스키마나 API가 바뀌면 계획서와 규칙 문서를 같은 PR에서 고친다.

## CI

GitHub Actions로 PR과 `main` 푸시마다 실행한다.

- 백엔드 빌드와 테스트(M0부터)
- Android 빌드와 단위 테스트(M4부터)
- gitleaks 비밀값 검사(M0부터)

CI에서 실제 Claude API를 호출하지 않는다. API 키도 CI에 넣지 않는다. 비밀값이 검출되면 머지하지 않고, 실제 값이면 폐기 후 새로 발급한다.

## 머지

- 리뷰어가 없으므로 PR에 자동 머지를 켜서 CI가 통과하면 합친다. 실패하면 원인을 고쳐 다시 푸시한다.
- 일반 머지(merge commit)로 브랜치 커밋을 `main`에 그대로 남긴다. Squash와 Rebase는 쓰지 않는다.
- 머지 커밋은 GitHub가 만들어 noreply 주소로 남는다. 작성자 이메일을 따로 지정하면 거부될 수 있으므로 지정하지 않는다.
- 브랜치 보호는 `main` 직접 푸시 금지와 CI 통과 필수만 켠다. 승인 리뷰 필수는 켜지 않는다.
